# prd_parse_and_cline_kanban_task_split
Instructions for AI agent: 用户触发该技能时，需严格按以下规则执行全流程，仅读取用户指定PRD文档，按固定模板输出，注意事项为固定内容，不得自行修改或生成。

## Usage
用户触发指令示例：
- 解析PRD并拆分Cline Kanban任务
- 读取PRD，拆分开发任务到Cline Kanban
- 解析指定路径/名称的PRD并拆分Cline Kanban任务

## Steps
1. PRD文档读取与解析
   仅读取用户明确指定的PRD文档，格式支持md、docx、txt；未指定时主动询问用户提供文档名称或路径；成功读取后提取核心需求、功能描述、业务规则等关键信息，确保需求理解无偏差。

2. 开发任务拆分
   基于PRD需求梳理核心功能模块，合并细碎且关联性强的需求，严格控制任务总数≤10个；每个任务独立可执行、边界清晰、不跨模块、不重复，适配Cline Kanban看板管理；存在先后顺序时标注依赖关系。

3. 输出模板（强制固定，不可修改）
```
   项目描述：
- 技术栈：{前端/后端技术栈}
- 统一返回体：{后端使用ApiResult封装，前端统一使用ApiResponse封装}
- 代码风格：{遵循项目统一编码规范（命名驼峰、分层架构、注释齐全等）}
- 工具类复用：{必须复用项目现有工具类（日期、字符串、加密等通用工具），禁止重复开发，当查询到项目没有相关工具类时才新增}

任务（序号）：{任务标题}
- 任务描述：{任务步骤清晰，独立可执行，边界清晰，不跨模块、不重复}
- 任务边界：{仅聚焦单一功能模块，不扩展额外逻辑、不跨模块修改代码}

注意事项：
- 如需执行终端/系统命令，直接输出纯命令字符串，多命令用英文分号分隔，禁止方括号包裹、禁止Python列表格式。

前置任务（如有）：
此任务依赖前置任务{任务序号}
```
4. 问题处理
   遇到以下情况立即停止执行，精准询问用户，不擅自猜测：PRD文档内容模糊、需求冲突或缺失；无法读取指定PRD文档；项目技术栈、工具类、返回体等规范不明确；命令执行异常；任务拆分边界无法界定。

5. 任务输出
   按固定模板逐条输出所有任务，可直接复制导入Cline Kanban；每个任务必含项目描述、任务、固定注意事项三部分，注意事项为固定文本，不得修改；存在依赖时补充前置任务；输出完成后提示用户确认，支持调整任务数量、边界或规范。
